# Voice Engine Research for Galaxy AI Voice & Subtitle Studio

Snapshot: 2026-08-01. Star counts are approximate and come from each repository's GitHub API metadata. This report prioritizes the actual target machine: Windows, Python 3.13.7, Intel Iris Xe Graphics reporting 1 GB AdapterRAM, and no NVIDIA CUDA runtime.

## Bottom line

For the current product, **edge-tts is the default** because its Vietnamese voices sound better on the target machine and need neither an API key nor local GPU inference. **sherpa-onnx with a Vietnamese Piper voice** remains the best maintainable local/offline fallback: it supports Windows, Python 3.13, offline CPU inference, and is still actively maintained. **Supertonic 3** is technically stronger for lightweight multilingual local quality -- 99M ONNX parameters, explicit Vietnamese, and no GPU requirement -- but its maintainer announced on 2026-07-23 that the repository will be archived with no further development or official support. It should therefore be an optional version-pinned engine, not the app's long-term default. [Supertonic retirement notice](https://github.com/supertone-inc/supertonic#readme)

For the shipped online quality mode, **edge-tts** exposes two Vietnamese Microsoft voices without an API key, but it depends on an unofficial client path to Microsoft's online Edge service. For a future local fallback beyond Windows SAPI, use a Vietnamese **Piper** voice through sherpa-onnx.

For local Vietnamese voice cloning, **VoxCPM2** has the strongest verified feature and license fit, but not the hardware fit: its official table lists about 8 GB VRAM for the 2B model. It should only be an optional, separately bundled CPU/Vulkan service and is likely to be slow on this machine. None of the heavyweight cloning engines is a good in-process default for Intel Iris Xe 1 GB.

## Ranked recommendation

1. **edge-tts as the shipped product default.** Very easy Python integration, no API key, current Vietnamese voices `vi-VN-HoaiMyNeural` and `vi-VN-NamMinhNeural`, and no local GPU cost. It is online-only, offers no voice cloning, and the LGPL client license does not grant rights to the Microsoft service itself. [repo README](https://github.com/rany2/edge-tts#readme) | [Microsoft voice list](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support)
2. **sherpa-onnx with Piper Vietnamese as the future local engine.** sherpa supports Windows x64, Python 3.13 wheels, and offline ONNX CPU inference. Piper explicitly lists `vi_VN` and does not need a GPU. Prefer the Apache-2.0 sherpa runtime over embedding the current GPL-3.0 Piper package; every downloaded voice still needs its own model-card license review. [sherpa README](https://github.com/k2-fsa/sherpa-onnx#readme) | [Windows wheel matrix](https://github.com/k2-fsa/sherpa-onnx/blob/master/.github/workflows/build-wheels-win-x64.yaml) | [Piper voices](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/VOICES.md)
3. **Supertonic 3 as an optional pinned local engine.** It has explicit Vietnamese, CPU-first ONNX inference, no GPU requirement, and a compact 99M model. However, the official README says the repository will be archived and receive no further development or support, so bundle a tested version and do not depend on its hosted Voice Builder. It does not include an official local zero-shot cloning pipeline. [README and retirement notice](https://github.com/supertone-inc/supertonic#readme) | [Python package definition](https://github.com/supertone-inc/supertonic/blob/main/py/pyproject.toml)
4. **VoxCPM2 as an experimental Advanced Voice Clone backend.** It explicitly supports Vietnamese, reference-audio cloning, voice design, and commercial use under Apache-2.0. Its official Python stack requires Python below 3.13 and documents about 8 GB VRAM; use a separate environment or the documented `llama.cpp-omni` CPU/Vulkan path, never the app's Python 3.13 process. [README and hardware table](https://github.com/OpenBMB/VoxCPM#readme)

## Recommended integration shape

Use a small engine adapter in the desktop app and keep synthesis outside the GUI thread:

```text
Galaxy desktop app (Python 3.13)
  -> Product default: edge-tts
  -> Offline fallback today: Windows SAPI
  -> Future local engine: sherpa-onnx + Piper vi_VN
  -> Local quality option: pinned Supertonic 3 / ONNX
  -> Advanced clone: separate VoxCPM2 worker/service only
```

Sherpa-onnx with a Vietnamese Piper model is the strongest currently maintained fit for Python 3.13, Windows, CPU inference, and Vietnamese. Supertonic remains a strong technical fit only if the app pins and owns a tested model/runtime snapshot after upstream support ends. Heavy PyTorch engines should not be installed into the app environment: pin each one in its own Python 3.10-3.12 environment and communicate through a local HTTP/JSON or subprocess protocol.

The first implementation ships an engine selector with `Edge TTS (Online)` as default and `Windows SAPI (Offline)` as fallback. Piper and pinned Supertonic can be added later as local engines. Voice cloning should remain a separately installed advanced feature until VoxCPM2 CPU/Vulkan speed is measured on this exact Intel machine.
